# Backtest — 2026-10-09

Channel signals replayed against Kraken Futures 1-minute trade candles under the
bot's rules. Numbers only; no channel message text is reproduced here.

- Code: `tools/backtest.py` as committed with this file, on top of `64e2b7d`.
- Data: `corpus/channel_history.jsonl` (channel history to 2026-10-05) and the
  candle/funding cache in `data/backtest_cache/` — both gitignored, not committed.
- All three runs used `--offline` (cached candles only, no new requests).
- Sizing: $30 margin per signal, fixed 10x, $300 notional.

Run offline, the tool cannot query Kraken spot candles, so it labels all 98
uncovered signals "no PF_ 1m candles and no spot candles". The online run of
2026-10-07 split the same 98 as 75 (finest spot candle reaching back is weekly,
which cannot order stop vs TP) and 23 (no candles at all). Every other line of
the baseline matches the 2026-10-07 online run except unrealised P&L on the 3
still-open trades ($13.03 here vs $19.65), which depends on the last cached price.

  - Channel instructions are applied as the bot would: strict-grammar closes close at market, cancels end trades with no fills, stop updates tighten only. Everything the classifier routes to a human is NOT acted on.
  - The corpus holds each message's LATEST text; a signal edited after posting is simulated as edited. The bot would have seen the original.
  - MAX_TOTAL_OPEN_MARGIN is not modelled (its live value is in .env, which this tool does not read); at most 2 trades x 6 symbols x $30 = $360 can be open.
  - Instrument tick and size increments are today's; historical ones may differ.
  - Signals are processed at their Telegram post minute (age 0): the MAX_SIGNAL_AGE_MINUTES gate never fires in a replay.
